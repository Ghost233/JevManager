# 设计规范

适用于 JevManager 的页面、组件、主题与桌面交互。要求强度沿用 [工程规范](engineering.md)。视觉目标是中性、紧凑、有清楚层次；LM Studio 和 oMLX 用于参考具体操作与布局，不代替产品规格。

## 信息与页面职责

- **必须**遵循 [规格的职责与视觉修订](spec.md#2026-10-05-用户修订职责与视觉)。新增操作先确定所在页面及发生时机，再设计控件。
- **必须**以名称、主要属性、真实状态和操作为首层信息。技术详情与诊断按需展开；说明文字只保留完成当前操作需要的信息。
- **必须**让界面状态来自实际业务状态。成功、就绪、兼容与运行中分别表达，并给失败显示简短原因与可执行的后续操作。
- **建议**页面采用稳定导航、标题与操作区、内容列表的层次。主要操作固定位置，相同操作使用相同名称与图标。

## 主题与组件

`lib/app_theme.dart` 是颜色、文字和公共控件外观的实现入口。具体值以主题代码为准；本文规定语义用途，新增页面复用这些角色。

| 角色 | 必须使用的主题语义 |
| --- | --- |
| 页面标题 | `textTheme.headlineSmall` |
| 区域标题 | `textTheme.titleMedium`；较小分组使用 `titleSmall` |
| 正文与列表内容 | `textTheme.bodyMedium`；需要强调的正文使用 `bodyLarge` |
| 元数据与辅助信息 | `textTheme.bodySmall` / `labelMedium` 与 `colorScheme.onSurfaceVariant` |
| 搜索及输入提示 | `inputDecorationTheme.hintStyle`，与已输入文字有可辨别的灰度层次 |
| 主操作与焦点 | `colorScheme.primary`；同一操作组保持清楚的主次关系 |
| 背景、内容与分隔 | `surface` / `surfaceContainer` 及 `outlineVariant` |
| 状态反馈 | 复用状态组件与语义色，同时提供文字或图标，保持浅色与深色可读 |

- **必须**通过主题及公共组件统一输入框、按钮、弹窗、状态和表格外观。页面特例必须说明用途。
- **建议**新增布局间距采用 4、8、12、16、24、32 logical pixels；区域间距大于行内间距。同级元素共享对齐线，长列表保持稳定的行密度。
- **建议**优先用分组、对齐和留白表达层次；边框和容器用于帮助识别区域，避免每个控件都独立包一层卡片。
- **必须**对长名称、路径与版本提供省略及查看完整内容的入口。文字缩放后仍保留主要操作和状态。

## 桌面交互

- **必须**按窗口可用空间布局，在声明的最小尺寸下保留关键操作。窗口扩大时限制表单与长文本宽度，列表可利用额外空间。
- **必须**让主要操作可通过键盘完成，Tab 顺序与视觉顺序一致、焦点可见。搜索支持 Enter；可取消的弹窗支持 Escape，并在关闭后合理恢复焦点。
- **必须**区分 hover、焦点、选中、禁用与执行中状态；执行中的操作提供真实反馈并防止重复提交。
- **必须**按 [应用生命周期规格](spec.md#mcp-与应用生命周期) 验证关窗、重开与明确退出。
- **建议**使用统一的公共组件呈现空、加载、失败和有内容状态；错误在发生的区域附近呈现。

## 界面修改的验收

1. 核对本次修改是否符合页面职责，沿相关操作走通，并检查可见状态与实际业务结果一致。
2. 在应用声明的最小窗口尺寸和常用尺寸检查布局；检查浅色、深色、放大文字及长内容。记录溢出、截断或不可操作的情况。
3. 用鼠标与键盘检查主要路径、焦点、Enter/Escape、执行中及失败恢复。涉及窗口行为时另做 Mac 原生验收。
4. 保存关键状态的截图及检查结论到相关 `docs/verification/` 记录，注明运行版本、窗口尺寸、主题和未验证项。首次采用组件样式时建立参考截图；后续按影响范围比较。

**必须**分别报告行为与视觉检查。Widget 测试能验证控件和状态；截图与真实窗口操作用于验证外观及桌面体验。仅 `analyze` 或构建成功不能证明界面验收完成。
