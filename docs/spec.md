## 问题陈述

用户希望在本机运行多个现成的 Jev 类决策模型，对同一份上下文和候选项并发判断，再将各模型意见、综合结果和分歧交给大模型作最终判断。

目前模型发现与下载、文件存放、格式识别、引擎兼容性和 MCP 接入分散在不同工具中。相同模型名称或 GGUF 后缀不保证加载能力，普通聊天模型也不自动具有决策概率接口。用户需要一个简洁的桌面管理应用完成整个闭环，并能继续使用 LM Studio 的模型库和运行能力。

## 解决方案

提供标准 Flutter macOS 桌面应用。用户通过 Hugging Face 搜索或仓库定位模型包，选择格式/量化变体，由内部解析完整资产集合并下载到可配置的模型库目录，识别本地模型资产，优先关联 LM Studio，必要时补充兼容引擎。

用户选择实际可用的席位组成委员会。一次咨询将同一决策请求并发发给各席位，等权综合成功席位的真实概率，保留原始意见、投票、分歧和失败情况，通过本机 HTTP MCP 返回给大模型。先以两个不同模型完成真实闭环，再增加席位。

界面参考 oMLX，采用紧凑导航、表格、必要状态和直接操作。没有初始化教程、步骤工作台或大段说明，也不以固定模型列表限制下载。

## 用户故事

## 实现决策

### 产品边界与结构

- 首版是本机运行的非 App Sandbox Flutter macOS 应用，首先接入 Codex；不交付浏览器产品或替换桌面技术栈。
- 功能围绕模型发现/下载与模型库、资产识别、引擎与实例、委员会咨询、MCP 接入组织。
- 桌面操作与 MCP 咨询共用应用业务逻辑。UI 负责输入和状态呈现，不另写一套综合算法；MCP 负责协议接入与结果返回，不另持有一套模型。
- 决策模型使用别人发布的现成权重，整个流程零训练；不声称 JevManager 发布自研模型。

### 界面与操作

- 参考 oMLX 的简洁、中性、紧凑管理界面，使用直接导航、模型表格及就地操作；去掉原型中的三方案切换器和大侧栏展示区。
- 模型下载入口是 HF 搜索/仓库与模型包选择；用户选择格式/量化变体，使用一个下载按钮，无逐文件勾选步骤。本地模型、下载任务、引擎、委员会和 MCP 可以直接访问，没有初始化流程或教程。
- 主界面只保留名称、版本/格式、大小、实际状态、进度和必要操作。详细文件、原始结果和技术诊断按需展开；错误就地简短呈现。
- 搜索结果、下载成功与决策兼容性是不同结论。普通聊天模型、未知格式或不完整资产仍可出现在模型库，但不能因此显示为可用决策席位。
- 有原型或替身数据时必须简短标识；正式界面不能显示模拟成功来代替真实结果。

### HF 搜索、下载与共享模型库

- 用户可以搜索任意模型关键词或输入 HF 仓库，选择模型包与格式/量化变体；内部解析必要权重、完整分片、tokenizer/config/head/模板等配套文件，保存在同一模型目录，不限制为几个固定候选。
- 获取实际仓库元数据，记录来源、固定 revision、文件、大小、可用哈希、格式和许可证信息。不因为模型卡宣称或文件名就判定引擎兼容。
- HF 直连为默认来源，LM Studio 代理为可切换来源。代理的小文件验证不能替代大文件、Range、续传及版本一致性验收；失败状态必须如实呈现。
- 用户设置模型库根目录，可以选择与 LM Studio 共用的目录；不自动迁移、复制、重命名既有资产，也不自动覆盖同名正式文件。
- 下载到临时资产，必要文件完整且可用校验通过后才完成安装。中断保留可恢复片段；只有来源支持续传且远端版本仍匹配时续传，否则提示重新下载。
- 模型库按模型目录/包展示；模型的格式/量化变体与具体文件在内部关联，辅助文件不单独作为模型行。底层发现资产记录实际位置、格式和指纹；有已知 manifest 时对照来源。缺少上游校验和时不声称来源已验证。
- 手动删除展示明确选中的文件与大小，由用户确认；不递归删除整个模型库。已知在用资产先停止使用，再处理删除。
- 离线仍可扫描、读取已缓存元数据和使用已就绪的本地安装；在线搜索与下载不可用时显示相应状态。

### 资产识别、引擎与实例

- 识别依据真实格式、架构、决策 metadata、head、tokenizer、模板和必要配套文件，而非仅凭名称或扩展名。
- 状态区分本地发现资产、完整模型安装、兼容引擎组合和实际就绪推理实例。adapter-only、encoder-only、缺文件、不支持的决策接口均不能直接进入可用席位。
- 引擎优先 LM Studio，通过公开 CLI/SDK/REST 与 runtime 管理入口关联，记录实际版本、提供方和实例标识；不直接依赖其内部捆绑 binary。
- 针对具体模型与引擎验证实际决策接口和概率输出。LM Studio 不支持时，提供经验证的其他引擎路径，包括适当版本官方 llama.cpp 或该资产必要的专用引擎。
- 引擎安装和更新绑定具体来源、版本与校验结果；下载成功不等于模型已加载或接口可用。
- 受管实例由 JevManager 创建并负责启停；接入实例由其他应用/用户创建，连接使用不改变生命周期归属。
- 明确退出可以卸载本应用通过 LM Studio 公开接口创建的受管实例，或停止本应用启动的独立引擎进程；不卸载原有接入实例，也不结束 LM Studio 应用或服务本身。

### 并发委员会契约

- 席位可配置，先验证至少两个不同模型；不硬编码三个品牌或声称同底座席位相互独立。
- 入口为 consult_jev_council，接收上下文文本 state 及具有稳定 id 和文本的 options。只咨询，不执行候选行动。
- 每轮使用同一席位与候选快照，并发派发到已就绪实例；不逐席等待，也不在咨询时临时下载或冷加载模型。未就绪席位明确不可用。
- 成功输出必须覆盖同一候选 ID，概率值有限、非负并符合概率约束。缺项、错位、非法概率或无定义分数不悄悄加入概率综合。
- 对成功席位的真实概率等权平均，返回完整综合评分和全部并列最高项。综合评分不称真实正确率或已校准置信度，平票不按输入顺序伪造唯一胜者。
- 保留每席原始答案/概率、实际选择、模型资产与 revision、引擎/提供方、耗时、状态和故障原因。
- 保留候选票数；首选投票分歧为一减最高票数占成功席位数的比例。分歧不证明模型独立性或校准质量。
- 默认整轮截止为 10 秒，全部成功可以提前返回。截止后回收有效结果和失败席位，晚到结果不修改已返回结果；取消等待不擅自停止常驻实例。
- 全部选定席位成功为 ok；至少一席成功但存在故障为 partial；零席有效为 failed，不以省略失败席位把 partial 变成 ok。
- 至少两席成功为 ensemble 并返回综合与分歧；仅一席成功为 single_model，保留原始意见但综合字段为空；零席成功为 none 并明确失败。

### MCP 与应用生命周期

- 使用本机 Streamable HTTP MCP，默认只监听 127.0.0.1。委员会入口与模型推理 REST 接口分开。
- 一个应用管理常驻实例，多个兼容客户端共用；连接与断开不自动创建或卸载另一套模型。
- 工具发现不必等待全部模型冷启动。结构化结果包含每席意见、综合、分歧和故障；文本兼容内容表达同一结果。
- 协议与 SDK 选择绑定实际 Codex 接入可验证的版本，不能混用不同 MCP 版本的协商与调用规则；遵守所选传输的本地访问要求。
- 提供 Codex 接入配置并完成一次实际工具发现、调用和结果消费；仅在配置中出现服务器名称不算通过。
- 关闭窗口后应用、模型和 MCP 继续运行，能够重新打开管理窗口。明确退出时停止接受新请求，收口进行中的咨询、受管实例及 MCP；不建立退出后继续工作的独立后台服务。

### 开发与交付边界

- 通用 Dart/widget 测试在容器执行，使用既有 Socktainer 上下文和用户规定的运行通道。
- 用户已明确允许 Mac 上准备 Flutter SDK 与构建必需依赖、编译应用、进行桌面/引擎联调，并运行应用内本机 MCP。这是范围明确的容器规则例外，不是无关依赖或系统变更授权。
- 不直接把被否决的原型 UI、模拟下载、模拟实例或示例 MCP 状态提升为生产实现。正式版本按本规格重写相应行为并验收。

## 测试决策

### 已由用户确认的测试边界

主要自动化测试从桌面和 MCP 实际共用的应用业务入口发起，经过真实下载状态、识别、实例管理及委员会逻辑；只在 HF 网络和外部推理提供方这些 I/O 边界使用可控替身。

测试验证可观察的输入/输出、文件变化、状态和并发行为，不访问私有方法、不逐行复刻算法，也不增加仅供测试使用的第二套业务接口。原生 UI 与真实模型/MCP 另做 Mac 联调，以证明替身结果之外的实际闭环。

### 功能与故障覆盖

- HF 搜索不依赖固定品牌；模型包/变体/revision 对应正确，用户只选模型与格式/量化，内部准确解析完整资产集合。覆盖单 GGUF、分片 GGUF、多量化仓库、Safetensors/config/index/tokenizer/head；不把文件详情或辅助文件当模型选择入口。
- 来源切换、下载中断、续传不支持、版本变化、校验失败、文件冲突、缺文件和离线都有外部可验证状态；既有共享文件不被扫描或下载自动改变。
- 手动删除只处理用户选定、可删除的文件；取消确认不改变文件，在用资产不能被静默删除。
- 识别区分普通聊天模型、完整决策资产、adapter/head 拆分、不支持格式及引擎未就绪；没有概率能力不能混入等权综合。
- 证明同一请求已向多席位并发派发，不使用依赖时间偶然性的串行测试；检查候选 ID、平均综合、并列最高、票数与分歧。
- 覆盖全成功、部分成功、单席成功、零席成功、非法响应、超时、晚到结果与取消等待；失败信息不可丢失。
- 检查 MCP 结构化与文本结果一致，工具发现不依赖模型已加载，客户端连接不重复创建模型。

### 本机与表现验收

- 至少两个不同的真实兼容模型进入就绪，经同一决策请求并发返回真实输出，再通过 Codex 实际调用并接收综合结果。
- 实测关窗继续、窗口重新打开、明确退出、受管实例收尾、接入实例保留及无遗留独立引擎进程。
- 使用已准备的 12 个中文合成规则案例，记录单模型和综合结果、并列项、失败及选项重排变化。案例不是训练数据或真实业务数据，不隐藏综合弱于单模型的情况。
- 分开冷启动与预热后咨询，记录具体版本、样本数、端到端和各席位耗时、延迟分位数及可实际取得的内存口径；未测指标明确未测。
- 容器测试、替身测试、原生 UI、真实引擎、真实下载和真实 Codex 调用各自记录，不能互相替代。
- 现有仓库没有正式业务测试可复用。旧原型与其已成功编译的结果不证明本规格的功能或可访问性验收通过。

## 2026-10-05 用户修订：职责与视觉

以下修订替代前文冲突的界面与引擎交互描述，后台真实性和委员会验收要求保留。

- 搜索输入提示使用辅助灰度，模型包与格式/量化保持主要选择；模型文件只作内部关联及按需详情。
