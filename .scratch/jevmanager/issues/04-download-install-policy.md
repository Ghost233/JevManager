## Question

在已证实的模型资产上，首版如何区分官方目录、用户导入和外部模型？用户已要求可设置存放路径并可共用 LM Studio 目录；下载源和代理、共享目录识别、版本固定、完整性校验、取消与断点恢复、离线安装、删除及占用中的文件采用什么用户可见规则？

用“一个模型包含多个必要文件、下载中断、已有安装被席位使用”的具体场景确定最小首版规则，不把所有可能功能都默认纳入。

## Answer

### 用户确定的首版范围

- JevManager 自己负责下载。默认 Hugging Face 直连，提供可切换的 LM Studio 代理来源；代理的大文件与续传能力仍需实际验收。
- 模型库根目录可设置，也可直接选择与 LM Studio 共用的目录。扫描既有资产，不自动搬迁、复制、重命名或导入 LM Studio。
- 共享目录中已有模型也可以在 JevManager 界面内手动删除；不限于本应用下载的模型。这个决定授权产品提供删除功能，不是授权当前会话删除任何现有文件。
- 用户在原型反馈中修正：下载必须通过搜索 Hugging Face 或输入仓库选择文件，不限制为固定候选模型。保留本地扫描；下载成功与模型决策兼容性仍分开识别。

### 实施边界

- HF 搜索与仓库文件列表展示实际来源 repo、当前 revision、文件、大小和可用校验和。用户选择具体版本/文件，不自动下载仓库的所有量化；原有兼容性证据用于识别与引擎匹配，不限制搜索范围。
- 新下载使用临时文件，未完成或校验失败不标为已安装。只有必要文件完整且校验通过才完成安装；不自动覆盖共享目录的既有文件。
- 下载停止或网络中断不修改既有正式资产。未完成片段可供恢复；仅当来源支持 Range 且远端资产仍匹配固定版本时续传，否则明确显示需要重新下载。不能以小文件代理验证代替大权重验收。
- 本地识别检查格式、架构、决策头及配套文件。已识别、资产完整、引擎兼容、推理实际就绪分别展示；普通聊天模型、adapter-only、encoder-only、缺文件或未知格式不直接成为可用席位。
- 下载资产对照目录中的预期校验和；本地既有资产记录实际指纹，有已知 manifest 时再核对来源。没有上游校验和不能显示为已验证来源，也不能仅凭名称或扩展名宣称可运行。
- 手动删除展示实际选中的文件及大小，并由用户在应用内确认。仅处理所选资产的明确文件，不递归删除整个共享模型库；已知仍被推理实例使用的资产先停止使用再删除。如何停止 LM Studio 或本应用实例由生命周期工单确定。
- 离线时仍能扫描本地资产、读取已缓存的仓库元数据、识别和使用已经通过引擎验收的安装；HF 在线搜索和下载不可用时显示状态。

上述边界落实既有的文件保留、完整性和真实验收要求，不代表下载器、扫描器或删除功能已经实现。该工单的产品范围已确定，后续以实际实现和验收验证。

### 验收

- 用户选择与 LM Studio 共用的模型库后，发现既有文件，扫描不改变其内容或路径。
- 同一候选资产可以选择下载来源；必要文件、固定 revision 和校验结果一致。中断、源不支持续传、校验失败和文件冲突均有真实结果。
- 缺决策头或不兼容引擎的文件不会被标为可用委员会席位。
- 已有共享资产也显示手动删除入口；取消确认不改变文件，确认仅删除明确选择且可删除的文件。
- 下载与识别完成后，资产能交给兼容引擎，参与用户要求的多模型并发咨询。
