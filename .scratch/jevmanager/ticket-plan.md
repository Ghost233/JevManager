# JevManager 实现工单拆分方案

2026-10-04 用户明确批准粒度和依赖，已按此方案逐张发布到 [实现工单索引](../jevmanager-build/index.md)，从 01 编号，与已解决的 Wayfinder 决策工单分开。当前尚未开始实现。

## 建议拆分

1. **紧凑桌面里的 HF 搜索与文件浏览**

   **被什么阻塞：** 无，可立即开始。

   **交付内容：** 用户在正式 Flutter macOS 应用中按关键词或仓库搜索 HF，查看真实文件、revision、格式与大小。建立供桌面和后续 MCP 共用的业务入口，以及容器行为测试路径；界面参考 oMLX，没有教程、固定模型下载菜单或模拟成功。可以独立演示一次真实搜索和文件选择。

2. **下载所选资产到用户模型库**

   **被什么阻塞：** 紧凑桌面里的 HF 搜索与文件浏览。

   **交付内容：** 从搜索结果选择具体文件，设置模型库目录和下载来源，看到真实进度与版本/校验结果。中断可恢复，同名冲突不覆盖既有文件；完整后成为模型安装。独立演示真实文件下载、失败和恢复，不把下载当作引擎就绪。

3. **共享模型库的扫描、识别与手动删除**

   **被什么阻塞：** 紧凑桌面里的 HF 搜索与文件浏览。依赖它提供的正式桌面壳、业务入口和容器验证路径，不依赖新下载。

   **交付内容：** 用户选择已有 LM Studio 共用目录，扫描真实文件，区分资产完整、不支持、普通聊天模型和待引擎检查状态；手动删除明确选中的可删除资产。扫描不搬迁或覆盖，在用文件先停止使用。使用已有资产即可独立演示。

4. **LM Studio 接入与实例能力检查**

   **被什么阻塞：** 共享模型库的扫描、识别与手动删除。

   **交付内容：** 用户关联 LM Studio，查看实际 runtime/版本、模型与实例，通过公开接口识别受管和接入实例，检查选定资产是否具有真实 decision 能力。支持组合可以产生真实结果；不支持或不可连接组合显示真实原因。不能以普通聊天输出或测试替身代替能力验收，也不预设 LM Studio 一定支持该接口。

5. **兼容补充引擎让决策资产实际就绪**

   **被什么阻塞：** LM Studio 接入与实例能力检查。复用其提供方、实例归属和能力状态契约。

   **交付内容：** 对 LM Studio 无法运行的决策资产，用户选择、安装并管理匹配的补充引擎，完成真实加载、启停和单模型概率响应。固定来源、版本与校验，至少让两种不同模型有实际可用路径。独立演示一个补充引擎和真实单模型咨询。

6. **两席真实并发咨询与等权综合**

   **被什么阻塞：** 兼容补充引擎让决策资产实际就绪。

   **交付内容：** 用户在紧凑委员会界面选择已就绪席位、输入上下文和候选项，收到真实并发结果、完整等权综合评分、并列项、原始意见、票数和分歧。记录实际派发与完成时间，候选 ID 不按展示顺序混淆；不声称综合值是正确率。

7. **超时、无效响应和部分结果的完整返回**

   **被什么阻塞：** 两席真实并发咨询与等权综合。

   **交付内容：** 某席位失败、未就绪、返回非法概率或超过默认 10 秒截止时，界面仍显示有效意见与明确故障。区分 ensemble、single_model、none 和 ok、partial、failed；晚到结果不修改已返回结果，取消不杀常驻引擎。可以独立演示停用一席后的部分结果，以及受控接口故障场景。

8. **Codex 通过本机 HTTP MCP 咨询委员会**

   **被什么阻塞：** 超时、无效响应和部分结果的完整返回。

   **交付内容：** 应用提供真实 loopback MCP，Codex 发现并调用 consult_jev_council，实际消费每席、综合、分歧及故障字段。UI 与 MCP 使用同一业务逻辑，多个连接不重复加载模型，文本和结构化结果一致；协议/SDK 与实际客户端验证匹配。

9. **关窗继续与明确退出的正确收尾**

   **被什么阻塞：** Codex 通过本机 HTTP MCP 咨询委员会。

   **交付内容：** 关闭窗口后 Codex 仍能咨询、窗口可重开；明确退出时 MCP 和受管实例收尾，LM Studio 本身及接入实例保留。通过实际连接、实例状态和进程结果演示，不只检查窗口回调。

10. **中文对照闭环与本机应用交付**

    **被什么阻塞：** 下载所选资产到用户模型库；关窗继续与明确退出的正确收尾。

    **交付内容：** 使用同一组 12 个中文合成案例，经实际引擎与 Codex 跑通单模型和委员会对照，记录结果、版本、冷/热耗时、失败与可测内存，并交付可直接运行的本机 .app。不把合成成绩当真实业务效果；此前各切片已有自身验收，这张只负责完整发布闭环及证据汇总。

## 依赖与验收说明

- 首个 frontier 只有“紧凑桌面里的 HF 搜索与文件浏览”；它交付有实际行为的第一条路径，不是单独的空壳或横向架构重构。
- 下载和本地库管理在首个切片后可以分别推进。引擎/委员会可以使用既有安装，不被新下载人为阻塞；完整交付再收口下载路径。
- LM Studio 的 unsupported 是可验证能力结论，不是为了通过工单而伪造支持。其优先级不阻止必要的补充引擎路径。
- 每张切片都包含相应桌面/业务/外部接口行为及容器测试；Mac 编译和真实联调遵守规格确认的例外。不能把测试集中拖到最后一张。
- 没有预重构工单：目前只有一次性原型，不需要先重构再建设正式业务。原型不直接提升为生产。
- 批准后仍按 to-tickets 模板独立发布，每张自包含、声明真实阻塞边，再交接 implement；本草案不授权直接开始功能实现。
