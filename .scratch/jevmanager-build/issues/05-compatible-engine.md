# 05 — 兼容补充引擎让决策资产实际就绪

**要构建什么：** 对 LM Studio 无法运行的决策资产，用户可以选择、安装和管理匹配的补充引擎，完成真实加载、启停与单模型概率响应，建立至少两种不同模型的可用路径。依据 [首版规格](../../jevmanager/spec.md)，固定具体资产/引擎组合，不构建臆测性的通用引擎插件平台。

**被什么阻塞：** [04 — LM Studio 接入与实例能力检查](04-lmstudio-provider.md)，复用提供方、实例归属和能力状态契约。

**状态：** ready-for-agent

- [ ] 为实际选定资产提供必要的兼容引擎路径，优先已有一手证据的官方 llama.cpp 或必要专用引擎。
- [ ] 引擎来源、确切版本、适用架构和校验结果可追溯，不把主线文档能力等同于任意已安装构建。
- [ ] 用户能看到安装、启动、实际就绪、停止及失败状态；不满足 head/模板/接口要求的组合不就绪。
- [ ] 至少两个不同模型有经过真实响应验证的可用路径，并保留每个组合的来源与限制。
- [ ] 受管进程/实例可以正确停止，启动或能力失败不遗留本应用的独立引擎。
- [ ] 容器行为测试覆盖安装/能力/实例状态边界；真实 Metal/Mac 加载和单模型输出另行验证。
- [ ] 不安装无关运行时、不改变既定容器后端，也不训练模型。
