## Question

用低成本界面原型验证从找到模型、下载和校验、启动并看到就绪、配置委员会、连接 MCP，到发起一次咨询并看到各席位结果的操作路径是否清晰？用户如何识别下载失败、缺少决策头、不支持当前引擎、引擎未就绪和某席位超时？

原型只回答界面与行为问题，由用户反馈决定。模拟状态必须标注模拟，不能把原型展示当作实际模型或 MCP 验收。

## Answer

用户否决原型的三套布局，并据展示结果确定以下首版界面约束：

- 参考 oMLX 的简洁模型管理界面，采用紧凑的导航、表格和必要操作；避免巨大品牌区、过大的卡片与稀疏布局。
- 模型下载由 Hugging Face 搜索或输入仓库开始，再选具体版本/文件；不把几个固定模型当下载入口。
- 删除初始化流程、步骤工作台和教程。模型库、引擎、委员会与 MCP 是直接可访问的功能入口。
- 删除大段说明文字。只显示必要字段、状态、简短错误和对当前操作有影响的信息；详细技术信息按需展开。
- 下载完成、资产完整、引擎兼容及推理就绪分开显示。缺文件、不支持、未就绪和超时使用状态与就地操作呈现，不通过教程解释。
- 委员会界面同时呈现各席位意见、综合评分、分歧与失败情况；原型/示例数据若出现，只保留简短而明确的标识。

本工单的结论是界面方向与交互约束，来源是用户对实际原型的反馈；不是对新界面成品的验收。旧原型只保留为反馈来源，当前没有完成第二版，不能直接提升为正式实现。

上述约束与已解决的下载、生命周期和委员会决定足以交接正式规格。实际 UI、真实 HF 下载、模型识别、引擎与 MCP 的实现和验收转入规格及后续实现工单。
