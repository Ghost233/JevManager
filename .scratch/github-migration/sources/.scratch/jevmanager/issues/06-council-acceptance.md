## Question

在用户已确定“多模型对同一请求并发判断，综合结果经 MCP 返回给大模型”的核心流程下，首版通用候选项决策的请求与咨询结果应表达什么？选择多少席位，如何处理无概率模型、同底座、分歧、超时和部分失败；哪些聚合可以先做，哪些需要真实校准数据才允许宣称？

与用户确定一组真实中文任务、单模型基线、委员会对照以及延迟和内存测量方式。区分模型返回的分数、概率、校准置信度与聚合统计，不把加权均值直接称为正确率或可信度。

验收需证明同一请求触发多个席位并发执行，并验证综合结果、各席位意见与分歧通过 MCP 返回且被大模型实际接收。不能只以多模型可启动、逐个手工调用或只返回单席结果作为委员会验收。

## Answer

### 用户确定的首版规则

- 席位可配置，先用至少两个不同且实际验证可用的模型跑通，不固定三个品牌或强行填满席位。
- 同一份上下文与候选项并发发给选定席位，对成功席位的真实概率向量作等权综合；同时返回各模型原始结果、投票与分歧。
- 综合值称为**综合评分**，不称正确率或经过校准的委员会置信度。首版不实现自定义权重或自动校准，后续真实评测再决定是否需要。
- 整轮初始截止预算为 **10 秒**。全部选定席位成功则提前返回；到截止时返回已完成结果及各未完成/失败席位，不等待无限期结果。该值是初始预算，不是本机性能承诺。
- 首轮先用规则明确的中文测试案例验收；用户真实任务效果后续单独验证。

### 请求与响应契约

- MCP 工具保持 `consult_jev_council(state, options)`。首版 `state` 是上下文文本，`options` 是具有稳定 `id` 与文本的候选项列表；选项不按展示位置充当标识。该工具只咨询，不执行候选行动。
- 每次调用记录请求标识、选定席位数、成功席位数、实际耗时和整体状态；每席记录实际模型资产/修订、引擎与提供方、原始答案/概率、选择、耗时、失败原因。
- 成功概率需覆盖相同候选 ID，数值有限、非负且符合概率约束。缺失候选、非法值、不同候选集或只有无定义分数的输出不能悄悄加入概率综合，标为无效/不支持并保留故障原因。
- 对成功席位集合 S，候选 i 的综合评分为 `sum(p_s(i), s in S) / |S|`。返回完整评分和全部并列最高项；平票不按输入顺序伪造唯一胜者。
- 保留各席位实际首选与票数，首选投票分歧为 `1 - 最高票数 / 成功席位数`。同底座/同模型来源信息保留，票数不代表意见相互独立，投票分歧也不代表概率校准。
- `status=ok` 表示全部选定席位成功；至少一席成功但有失败为 `partial`；零席有效为 `failed`。每个选定席位都有结果或明确故障，不以忽略失败席位把 partial 变成 ok。
- 两席及以上成功时 `mode=ensemble`，返回综合评分和分歧；仅一席成功时 `mode=single_model`，保留其意见但综合字段为 null；零席成功时 `mode=none`，综合字段为 null 并返回失败。单模型意见不冒充委员会共识。
- 采用 MCP 对应版本的结构化工具结果，文本兼容内容与结构化 JSON 表达同一结果。最终输出必须含综合与分歧字段，替换研究阶段只覆盖单席排序的草案。

### 并发与故障边界

- 已就绪实例接收同一请求时并发派发，不逐席等待前一模型完成；同一次请求使用一致的席位和候选快照。
- 默认 10 秒预算覆盖本轮咨询的调度与等待。冷加载由启动器单独完成，不在一次咨询里临时下载或装载模型；未就绪席位明确 unavailable。
- 超时后取消或停止等待未完成的请求，晚到结果不修改已返回的综合结果。取消不能擅自结束常驻引擎或其他客户端调用。
- 单席超时、连接失败、非法响应或不支持输出只影响该席位；整体故障和部分故障分别表达。明确退出应用时的新请求拒绝与进行中咨询收口沿用生命周期规则。
- 记录派发/完成时间证据证明并发调用，不因这一点就宣称 GPU 内核同时执行或总耗时必然下降。

### 首轮验收数据与标准

初始数据为 [中文决策冒烟案例](../../../benchmarks/fixtures/zh-decision-smoke.json)，包含 12 个合成规则案例，覆盖否定、明确优先级、无优先级冲突、信息不足、约束、边界及候选重排。它不是训练集，不是用户真实业务数据，也不足以证明泛化或校准质量。

- **功能验收**：以可控接口响应验证等权公式、并列最高项、投票分歧、候选 ID 映射、无效概率、10 秒截止、部分/单席/零席结果和 MCP 消费。替身结果标为替身，不能当作模型推理验收。
- **本机闭环**：至少两个不同的实际兼容模型经对应引擎进入就绪；发起同一请求，记录并发区间、真实原始输出和综合结果，并由 Codex 实际调用和接收。
- **中文表现**：逐个模型与综合结果使用相同案例，记录唯一正确首选、并列首选、失败和重排后的变化；不隐藏综合弱于单模型的情况。不先设不存在数据依据的精度保证。
- **资源与耗时**：分开冷启动与预热后咨询，记录版本、样本数、端到端及各席位耗时，报告延迟分位数和能实际测得的内存口径；读不到的指标标为未测，不把权重文件大小当峰值内存。
- 网络超时、部分失败和无效响应属于接口集成验收；中文语义案例不代替这些故障注入检查。

本工单完成规则决定与测试数据准备；尚未运行测试案例、加载模型、进行资源测量或启动实际 MCP。
